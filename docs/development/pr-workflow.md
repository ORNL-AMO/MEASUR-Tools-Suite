# Agent-Assisted Pull Request Workflow

Use this checklist when an agent prepares a MEASUR Tools Suite PR. Human-only PRs follow [CONTRIBUTING.md](../../CONTRIBUTING.md) and use the general [PR template](../../.github/pull_request_template.md) without agent review records. No standalone Codex CLI is required.

1. **Scope.** Resolve the intended base, linked Suite work, compatibility approval, and applicable Desktop impact. A child PR may target a feature branch; do not assume `develop`. Preserve unrelated work.
2. **Implement and validate.** Keep applicable C++, embind, TypeScript, tests, and algorithm docs synchronized. Run the checks selected by [AGENTS.md](../../AGENTS.md#testing-expectations) and [BUILD.md](../../BUILD.md). For Markdown-only changes, run `npm run check:docs` and whitespace checks rather than unrelated native/WASM builds. Record actual results and limits.
3. **Context-aware self-review.** The development agent reviews the full candidate against the original requirements, approved compatibility decisions, formulas/units, tests, docs, and downstream contract using [measur-code-review](../../.github/skills/measur-code-review/SKILL.md). The verification persona can supply this stage if it covers the exact candidate. Resolve authorized in-scope issues and commit intended changes.
4. **Independent fresh review.** Freeze the clean committed comparison and follow [fresh review](fresh-pr-review.md). Start without inherited development history, using the development agent's model/effort and no self-review conclusions. Present findings and validation gaps; resolve or explicitly disposition them, rerun affected checks, and repeat both stages after changes. No unresolved P0–P2 finding may remain when the PR opens; use the existing readiness rubric.
5. **Publish.** Obtain explicit publication authorization, honoring authorization already given. Fetch the target and verify both review records still cover the current branch, base, head, merge base, and clean checkout. Fill applicable sections of the general PR template, then append the [agent review records](pr-review-record.md). Link related Suite/Desktop work without auto-closing issues unless requested. Verify the resulting PR refs, body, and initial checks; do not force-push, assign reviewers, label, approve, or merge without authorization.
6. **Human review and delivery.** Retain required human/SME decisions and branch protection. After source changes, rerun affected validation and both review stages. Follow the [Suite-to-Desktop release sequence](suite-desktop-change-workflow.md#release-and-verification-order) when applicable. Record post-push CI/beta evidence in the PR; do not create evidence-only follow-up commits that restart publication.

**“Prepare a PR to <base>”** triggers preparation and both reviews without publication. **“Let's open/update a PR to <base>”** also authorizes the corresponding publication after readiness checks and required decisions. Resolve an omitted target from the request or established branch context.

An existing PR may request a fresh review alone, without claiming an author-context self-review occurred. Results return in chat; posting GitHub comments or changing a PR description requires explicit authorization. Before publishing findings, confirm the PR still matches the reviewed commits and anchor comments to the current diff. GitHub-hosted reviews, including configured Copilot review, remain separate and advisory.

These are agent instructions and visible review evidence, not an installed GitHub bot, enforced status check, or human approval. If the runtime cannot explicitly start without history, disclose that limitation instead of silently substituting self-review or the standalone CLI.
